# 실제 모델 웹 대시보드 비교 · 2026-09-25

## 공개 요약과 로컬 원자료

이 Markdown은 실험 결과의 공개용 요약입니다. 두 정적 웹 산출물(`native/dashboard/`, `active/dashboard/`), `data.json`, 원본 transcript, 채점 스크립트, 브라우저 캡처는 **민감정보를 포함할 수 있어 로컬에만 보관**합니다. 따라서 공개 Git 저장소만 복제해서 두 웹을 실행하거나 브라우저 검사를 재현할 수 없습니다. 원자료가 있는 로컬 복사본에서는 각 dashboard 폴더를 loopback HTTP 서버로 제공해야 하며 `file://`로는 데이터를 읽을 수 없습니다. 보고된 재현 조건·후속 검사 오류와 그 한계는 아래에 그대로 남깁니다.

## 조건과 원자료

- 실제 Claude CLI의 **동일 Main 모델 `gpt-6-sol`, effort `high`**, 동일 프롬프트·데이터·저장소 스냅샷(`6f9eb613…a709c3d`), 분리된 임시 HOME과 프로젝트. Jev `off`(native) 대 `active`; 순서는 native 다음 active. 양쪽 각각 Agent 위임 **1회** 관측. 최대 48턴·CLI 비용 상한 $3·경과 시간 상한 720초였지만 모두 상한 전 종료. 허용한 웹 파일 세 개만 변경했고 입력 데이터 해시는 유지됐다.
- active에서 실제 Jev HTTP **2건, 모두 200·schema valid**, upstream usage 입력 3,934·출력 502. 실제 라우팅 적용 PASS, child 모델 `gpt-6-sol` 관측. `effort_status` 원본 검증기는 `INCONCLUSIVE`였지만 별도 typed child transcript에서는 CLI effort `high`가 확인됐다. 이는 제공자 내부 추론량의 증명이 아니다. native도 child에서 `gpt-6-sol`/`high`가 관측됐다. **이 쌍에서는 선택된 모델·effort가 달라진 것이 아니다.**
- 수치는 코딩 CLI 프로세스의 시작/종료 시간과 `result.usage` 기록이다. 별도 브라우저 채점 시간은 아래 코딩 작업 시간에 넣지 않았다. 로그·route·요청은 각 `trial.json`, `transcripts/`, `real-jev-http.json`에 있다. 일부 child transcript의 usage는 완료 이벤트가 없어 전체 child 토큰으로 단정할 수 없다.

TypeSafe 청구액도 알 수 없고 Jev 응답에는 캐시 토큰 필드가 없어 0으로 가정하지 않았다. Jev 두 HTTP 소요 시간은 합계 약 1.287초이므로 +39.841초 전체를 Jev 네트워크 지연으로 돌릴 수 없다.

## 산출물 기능과 실제 사용성

**두 후보 모두** 동일 데이터의 3행·요약 2/3 대 3/3·+55.1% 시간 합계·기능/자체 테스트·CLI 표시 비용 및 범위 설명을 제공한다. 실제 서버와 Chrome CDP를 사용해 필터, 교차 필터 빈 결과/초기화, 시간 양방향 정렬, 마우스/Enter 상세 열기, 모바일 주요 요소를 확인했다. 두 후보 모두 **수정된 브라우저 검사 9/9**이며 그 실행에서 앱 콘솔 오류·필수 리소스 실패는 0건이다. 로컬 데이터와 결과물은 수정 없이 검사했다.

하지만 **9/9를 곧 전체 제품 목표 충족이라고 할 수 없다.** 후속 390px 실제 viewport 측정에서 명시된 ‘문서 전체의 가로 넘침 없음’ 요구사항의 거짓 음성이 드러났다:

| 390px Chrome 모바일 | native | Jev active |
|---|---:|---:|
| 화면/document client width | 390px | 390px |
| 문서 전체 scroll width | **390px (통과)** | **940px (550px 넘침, 실패)** |
| 비교표 client / content width | 356 / 356px | 360 / 1,000px |
| 초기 private-env 상세 버튼의 x 좌표 | 273–348px | 940–1,013px (화면 밖) |

측정은 로컬 전용 `mobile-layout-probe.py`, `mobile-requirement-audit.json`에 보존했다. active는 비교표에 내부 가로 스크롤 영역과 키보드 포커스 가능한 `role="region"`을 제공하지만, **문서 너비까지 늘어나는 문제는 별도**다. 후속 모바일 실클릭에서는 native 상세가 표시되고 목표가 viewport로 이동했으나, active 버튼은 바로 보이는 390px 영역에서 클릭 좌표를 얻지 못했다. 이는 CDP 스크롤/좌표계의 영향도 배제하지 못하므로 단독으로 ‘버튼 불능’이라고 판정하지 않고, 위 반복된 문서 넘침 수치를 필수 조건 실패의 근거로 쓴다.

시각 캡처를 직접 확인한 결과 native는 데스크톱에서 세 요약 지표가 첫 화면에 함께 보이고, 작업별 시간 차이도 바로 읽힌다. 모바일에서는 비교표를 카드로 바꿔 버튼을 가로 스크롤 없이 노출한다. 단, 모바일 요약 제목 옆 보조 문장은 밝은 배경에 밝게 나타나 가독성이 떨어지고, 데스크톱 상세 패널은 클릭 직후 화면 아래에 일부 걸칠 수 있다. active는 통일된 편집형 레이아웃, 결과/테스트/시간/비용을 묶은 명확한 열 구성 및 데스크톱에서 한 화면에 보이는 상세 패널이 장점이다. 대신 큰 도입부로 핵심 수치가 데스크톱 첫 화면 아래로 밀리고, 모바일 표와 문서의 넘침은 명시적 요구를 충족하지 못한다. 두 후보 모두 키보드 Enter/필터/초기화는 통과했다. 자동 접근성 검사나 실제 장애인 사용자를 통한 평가는 **수행하지 않았다**.

**이 한 웹 과제의 판정:** 정해진 9가지 동작은 동률이나, 확인된 모바일 요구 충족은 native만 성공. 코딩 시간·Main 토큰·CLI 표시 비용도 native가 적다. active의 데스크톱 정보 구성/시각 품질이 전부 열등하다는 결론은 아니며, 한 쌍에서 Jev의 일반적인 품질·성능 우열을 증명하지 않는다.

## 채점기 오류 및 정정 이력 — 숨기지 않음

1. 모델 실행 **전** SHA-256으로 고정한 로컬 전용 `browser-grade.py` (`52f510…fa5a9433d`)와 `browser-cli.mjs`로 처음 채점했을 때 **두 후보 모두 0/9**로 기록됐다. 그러나 Chrome의 자동 `/favicon.ico` 404를 앱의 필수 리소스 오류로 세었고, 스크롤 애니메이션 완료 전에 클릭 좌표를 판정했으며 일부 Chrome 실행이 시간 초과됐다. 이는 제품 0/9의 근거가 아니다. 첫 실행의 모든 케이스와 캡처는 `native/browser/`, `active/browser/`에 그대로 남겼다.
2. 후보를 바꾸거나 모델을 재실행하지 않고, 204 favicon 응답·비동기 데이터 준비 대기·스크롤 후 실제 마우스 이벤트·Chrome 화면 배율 및 타임아웃을 수정한 로컬 전용 `browser-grade-v2.py` (`b1454d…ad16406cf010`)와 `browser-cli-v2.mjs` (`6bd38a…34e15be`)를 양쪽에 **동일하게** 적용했다. 이 사후 정정의 9/9는 사전 채점기의 성공으로 소급하지 않는다. 원본과 v2 JSON을 모두 보존한다.
3. v2도 모바일 너비 검사에 `scrollWidth <= window.innerWidth`를 썼다. active에서 `innerWidth=940`으로 확장되는 동안 실제 `documentElement.clientWidth=visualViewport.width=390`이었다. 따라서 v2의 모바일 사례는 **거짓 음성**을 포함한다. 명시적 요구를 `scrollWidth <= documentElement.clientWidth`로 다시 확인한 값은 위의 별도 후속 감사이며 9점에 조용히 더하거나 소급 교체하지 않았다.

## 재현·한계

[사전 비교 프로토콜](PROTOCOL.md)은 공개하지만 원본 `data.json`, 보관된 두 웹, Chrome 검사 스크립트와 캡처, `trial.json`, `token-audit.json`, `browser-v2/browser-grade.json`은 로컬 전용이다. 로컬 실행기 `paired-run.py`도 당시 `/private/tmp/jev-real-work-comparison.py`에 의존하므로 다른 기기에 그대로 이식할 수 없다. 원본 프롬프트는 로컬 `native/task.txt`, `active/task.txt`에 보관했다. **공개 복제본만으로 재현할 수 없다는 제한**과 보관 원자료의 민감정보 때문에 외부 검증 가능성이 낮다는 점을 명시한다. 비교 표본은 **새 웹 과제 한 쌍**으로, 시간·토큰 차이에 작업 순서, 모델 변동, 코드 크기/의사결정 차이가 섞인다. 최종 청구액·제공자 내부 연산량·외부 사용자 만족도는 관측되지 않았다.
