# 3.2.0 — decision kernel, skill routing, advisory supervisor, 2026-11-25

기존 native hook의 모든 Jev 판단(위임 분류·프로필 선택·실패 분류·읽기 조언)을 provider-agnostic **decision kernel**(`src/kernel/`)의 지점(`delegation.classify`, `delegation.profile`, `failure.classify`, `read.advice`)으로 옮겼습니다. 기본 설정(`judges:['jev']`, `active`)에서는 hook 출력이 이전과 byte 단위로 같고 judge 호출 횟수도 같습니다. 지점별 `off|shadow|active` 모드와 `jev|openai|local` judge 체인, 낮은 확신 시 다음 judge로의 escalation, 원문 없는(해시·숫자·선택지 이름만) decision log(`stateDir/decisions-log`, 0600/0700)와 calibration 보고(`scripts/decisions.mjs`)를 추가했습니다.

새 지점 두 개는 기본 **off**입니다. `delegation.skills`는 위임 경계에서 프로젝트 `.claude/skills`와 `JEV_SKILL_DIRS`의 skill 카탈로그를 BM25로 좁힌 뒤 judge 확률로 load/consider를 정하고, `active`일 때만 routing packet 뒤에 이름·경로·확률만 담은 `<jev-skills>` 블록을 붙입니다(설명·본문은 주입하지 않음, `maxContextChars`를 넘으면 블록만 생략, 동일 tool id 재호출은 저장된 텍스트로 동일하게 재현). custom agent·명시적 native 설정·중첩 위임·resume 등 기존 보존 guard가 skill 작업보다 먼저 적용되며, skill judge 실패·지연은 라우팅을 실패시키거나 route deadline 이상 지연시키지 않습니다. `supervisor.outcome`은 이 확장이 라우팅한 동기 위임의 보고 텍스트만(비밀 유사 문자열이면 전송 생략) 판정해 `complete|retry|replan|escalate`와 근거 수준을 **조언으로만** 표시하며, 확신이 `kernel.supervisor.confidence` 미만이면 기존 일반 문구를 유지합니다. 자동 재시도·respawn·차단·권한 변경은 없습니다.

설정: `config.kernel`(없거나 일부만 있는 기존 설치 config는 기본값으로 병합), env `JEV_SKILLS_MODE`, `JEV_SUPERVISOR_MODE`, `JEV_SKILLS_JUDGES`, `JEV_SUPERVISOR_JUDGES`, `JEV_DECISION_JUDGES`, `JEV_SKILL_DIRS`, `JEV_OPENAI_DECISIONS_APPROVED`, `JEV_OPENAI_DECISIONS_MODEL`, `JEV_DECISION_LOG`(잘못된 값은 `INVALID_<NAME>`). `OPENAI_API_KEY`는 private `.env`에서 runtime env로만 전달되고 config에는 저장하지 않습니다. `policyFingerprint`에 kernel 설정이 포함되어 설정 변경 시 대기 중인 호출이 무효화됩니다. 설치기는 `src/kernel/`을 포함해 복사하고, `npm run check`는 하위 디렉터리까지 구문 검사하며, `scripts/skills.mjs --judge config --config <path>`는 설정된 judge 체인과 decision log를 사용합니다.

검증 범위: 2026-11-25 격리 실행(`scripts/test-all.sh`)에서 Node **498/498**, 구문 **61개 모듈**, 독립 검증기 self-test와 offline suite가 통과했습니다. 모두 mock judge·loopback 서버·주입된 fetch를 사용한 로컬 계약 검증입니다. OpenAI Decisions wire 계약과 기본 모델 이름은 실제 API로 확인하지 않았고, 실제 Jev/OpenAI 판단 품질, skill 선택의 정확도, supervisor 조언의 유용성과 calibration은 **NOT_RUN/미입증**입니다. `local` judge는 calibration되지 않은 어휘 휴리스틱입니다.

3.2.0 후속 보완 2(2026-11-25, 릴리스 전): skill 후보 검색 방식 `kernel.skills.retrieval`(`lexical` 기본 / `adaptive` / `full`)을 추가했습니다. **기본은 `lexical`이라 기본 동작은 그대로**이고 `npm run compare:default`는 차이 0입니다. `adaptive`는 작업의 어휘 신호(작업의 서로 다른 token 중 카탈로그 어휘에 있는 비율, `lexicalCoverage`)가 `minCoverage`(기본 0.25) 미만일 때, `full`은 항상 카탈로그 전체(최대 `maxJudged` 64개)를 judge에게 보냅니다. 넓은 판정은 요청당 `chunk`(기본 32)개 이하로 고르게 나눠 동시에 보내며 기존 예산 하나를 공유하고(추가 시간·재시도 없음), 전체 `need`는 요청별 최댓값, 실패한 요청의 skill만 `judge_unavailable`입니다. 요청마다 선택 지점 요청 상한·circuit에 세어지고 decision log record를 남깁니다(record의 답 상한 64 → 65). 결과에 `retrieval {mode, wide, lexicalSignal, requests, failed, judged, dropped}`와 `decisionIds`가 추가됐습니다. 검증 오류 `INVALID_KERNEL_SKILLS_RETRIEVAL`/`_MIN_COVERAGE`/`_MAX_JUDGED`/`_CHUNK`, env `JEV_SKILLS_RETRIEVAL`, `JEV_SKILLS_MIN_COVERAGE`, `JEV_SKILLS_MAX_JUDGED`, `JEV_SKILLS_CHUNK`, CLI `--retrieval`. **동작 변경 1건**: `local` skill judge는 어휘 신호가 0이거나 `minCoverage` 미만이면 need 0을 확신 1로 답하는 대신 기권(`LOCAL_ABSTAIN`)합니다. `local,jev` 체인은 그 경우 Jev로 넘어가고, `local` 단독(CLI 기본 포함)은 `status: unavailable`을 냅니다. 개발용 160건의 오프라인 분석(API 미사용, `qa/kernel/dev-retrieval-analysis.mjs`)에서 gold skill이 judge에게 도달하는 비율은 `lexical` 0.708(한국어 0.408) → `adaptive` 0.25에서 0.950(한국어 1.000) → `full` 1.000이었습니다. 이는 상한이며, 넓게 보여 줄 때의 judge 정확도·지연·토큰은 미측정입니다.

(4) **수집기**: `modelMatch`가 `exact`|`declared`|`alias-undeclared`|`mismatch` 네 값이 됐습니다(이전 기록의 `alias`는 그대로 읽음). 행은 앞의 둘에서만 만들고, 뒤의 둘은 `effective_model_alias_undeclared`, `effective_model_mismatch`로 셉니다(이전 이름 `effective_model_differs_from_profile_backend`는 없어짐). `alias-undeclared`이면 요약의 `modelMatch.undeclared`가 **어느 registry 항목에 어떤 id를 선언해야 하는지** 알려 주되 registry에는 쓰지 않습니다. 새 보류 이유: `task_ran_on_several_models`, `resolved_model_disagrees_with_transcript`, 그리고 context 관련 `session_ran_under_default_evaluation_context`, `session_ran_under_another_evaluation_context`, `route_evaluation_context_unknown`. **행은 세션이 실제로 실행된 context의 이름으로만 만듭니다**(이전에는 기본 context로 돈 세션에 나중에 `--evaluation-context`를 줘도 행이 만들어졌습니다. 그 길을 막았습니다). `importer_refuses:STALE_EVIDENCE_PROFILE`은 다른 이유가 있어도 함께 셉니다. (5) **hook**: `PostToolUse`의 `Agent` 결과에 있는 `resolvedModel`을 모델 id 형식일 때만 `spawn_observed` 이벤트에 남깁니다(hook 출력은 그대로). 수집기는 그 값과 Main 기록의 같은 값을 서브에이전트 기록의 모델과 대조합니다. (6) **도구**: `doctor.mjs` 출력에 `evidence`(활성 항목별 선언 id, 받아들이는 모델 id, 가져오기 가능 여부), `collect.mjs --report`에 일치 종류별 수와(`--config`일 때) 평가 저장소 요약, `feedback.mjs --report`(읽기 전용: 프로필별·일치 종류별 행 수, 현재/낡음).
